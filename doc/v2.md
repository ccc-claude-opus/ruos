# ruos v2.0 規劃

狀態：使用者確認（2026-10-31）。v1 是 tag `v1`（`c83a916`）：同一份核心跑在 wasm、RISC-V、ARM，五個平台全部通過。

## 方向

v1 的前端和後端都用 ruos 自己：網站的資料庫、服務也要在 ruos 裡用 `no_std` 的 Rust 重新寫，代價太大。v2.0 改成：

- **前端是 ruos**：只跑在瀏覽器裡（wasm）。教 capability、pod、shell 與 Linux 指令；能跑現成的 wasm 程式（WASI）。
- **後端是桌機的 OS**：`ruos serve`（Rust，tokio）跑在一般的作業系統上，直接用現成的軟體：SQLite（`rusqlite`）、PostgreSQL（`tokio-postgres`）、Redis（`redis`）……
- **兩邊用 capability 溝通**：後端的每個服務在 ruos 裡都是一個 capability（像 v1 的 `http`）。只有拿到的程式才能用。

RISC-V 與 ARM 都放棄。

## 已決定的事（使用者確認）

1. **後端用 Rust**，但可以呼叫其他語言寫的軟體（PostgreSQL、SQLite、Redis），也可以用 tokio 這類套件。
2. **前端做 WASI**（preview1，`wasm32-wasip1`），讓現成的 wasm 程式在 ruos 裡跑。
3. **kube、serverless、對外入口留著**：它們本來就只用到 wasm 與 ruos serve，留著當教材；之後函式可以用後端的資料庫。
4. **自己寫的 SQL 服務廢棄**：前端的資料庫用 WASI 版的 `sqlite3`（wasi-sdk 編的，不是官方給瀏覽器 JS 用的 `sqlite3.wasm`）；共用的資料放在後端的 SQLite / PostgreSQL。廢棄的程式留在 `build/v1-db.patch` 與 `build/v1-db-untracked.tgz`（git 不追蹤）。

## 步驟

1. **清理**（完成）：拿掉核心的 riscv64 / aarch64（分頁、trap、SMP 排程、裝置）、`services/blk`、`services/net`、`virtio/`、`services/wasmrt`、QEMU（run.sh、test.sh、`ruos riscv64|aarch64`）；映像只建 wasm32；測試只剩 host 與 wasm；版本 2.0.0。
2. **後端改用 tokio**（完成）：ruos serve 改成 axum + tokio-tungstenite，協定不變；對外入口改成 server 主動推送的 WebSocket（v1 是 long polling，因為 tungstenite 的同步 API 不能同時讀寫）。
3. **後端服務是 capability**（完成；PostgreSQL 沒有測過）：ruos serve 的設定宣告有哪些服務：`sql:NAME`（SQLite 檔案，或 PostgreSQL 連線字串）、`redis:NAME`。在 ruos 裡，init 把它們交給 shell；`run IMAGE sql:app` 與 kube 的 `uses = ["sql:app"]` 交給別的程式。shell 有 `sql`、`redis` 指令。
4. **前端 WASI preview1**：
   - WASI 轉接層用 Rust 寫，和程式在同一個 Worker、共用同一塊 memory（載入時把程式自己定義的 memory 改成 import）。先單獨驗證這一點。
   - capability 的對應：預先開好的目錄 = 名稱空間的 `fs`；stdin / stdout / stderr = console；參數與環境變數 = `exec:`；時鐘、亂數 = 核心的系統呼叫。preview1 沒有 socket：網路經 `http`。
   - podimg 把現成的 `.wasm` 包成映像；試跑 uutils coreutils、sqlite3、Lua、QuickJS。
5. **範例、課程、發布**：網站範例（留言板、待辦、wiki、短網址、天氣）用後端的資料庫；WASI 一課；發布 2.0.0，tag `v2.0`。

每步只測 host 與 wasm，各自 commit。
